일반물리 I (PHY1001) 강의 홈페이지를 Astro + Markdown으로 만들었다. 핵심 아이디어는 단순하다: **슬라이드, 시뮬레이션, 아이패드 판서를 웹 브라우저 하나에서 전부 처리한다.** → [yw-choi.github.io/PHY1001](https://yw-choi.github.io/PHY1001/)

### 왜 만들었나

파워포인트로 강의를 해오면서 두 가지가 계속 불편했다. 물리 강의는 수식 유도가 핵심인데, PPT에서 수식을 고치려면 매번 수식 편집기를 열어야 한다. 시뮬레이션을 보여주려면 프로그램을 따로 띄워야 해서 강의 흐름이 끊긴다.

웹으로 옮기면 이 두 문제가 해결되는 것은 물론, 하나를 더 할 수 있다 — **슬라이드 위에서 직접 판서하는 것.** 아이패드 + 애플펜슬로 슬라이드 위에 그리고, 슬라이드를 넘겨도 판서가 보존되면, PPT와 판서 앱을 왔다 갔다 할 필요가 없어진다.

### 슬라이드 + 판서

Markdown으로 작성한 슬라이드를 렌더링하는 커스텀 SlideEngine 컴포넌트를 만들었다. `---`로 슬라이드를 구분하고, KaTeX 수식은 서버사이드 렌더링으로 로딩이 빠르다. 12개 챕터 분량이다.

SlideEngine의 핵심은 드로잉 캔버스다. 펜 5색과 지우개 3단계를 지원하고, 아이패드 애플펜슬에 최적화했다. Palm rejection으로 손바닥 터치는 무시하고, 펜 입력만 인식한다. 각 슬라이드의 판서는 IndexedDB에 자동 저장되어 새로고침하거나 다른 슬라이드에 갔다 와도 유지된다. 드로잉 품질을 위해 quadratic Bezier curve 보간을 적용했고, 임시 계산용 scratch pad도 별도로 둔다.

### 시뮬레이션

24개의 HTML5 Canvas 기반 인터랙티브 시뮬레이션을 만들었다. 자유낙하, 포물선 운동, 에너지 보존, 충돌, 관성모멘트, 사다리 평형 등. 슬라이더로 파라미터를 조절하면 실시간으로 물리량이 계산되고, `<!-- sim:filename.html -->` 디렉티브로 슬라이드에 직접 임베드된다. 수식은 KaTeX 캔버스 오버레이로 통일하여 그리스 문자나 아래첨자가 깨지지 않는다. Playwright e2e 테스트 281개로 검증했다.

별도로 전자기학·광학·양자역학 범위의 시뮬레이션 20개를 이전에 만들어 둔 것이 있어서, 합치면 총 44개다. 일반물리 II에서도 활용할 예정이다.

### 다이어그램

교과서 그림은 저작권 문제로 사용할 수 없어서 약 60개의 SVG 다이어그램을 직접 제작했다. 서강대 빨간색(`#8B0029`)을 주색으로 통일했다. SVG라서 수정이 필요하면 텍스트 편집기에서 바로 고칠 수 있다.

### 개발 과정

전체 약 3주, 실질적 집중 작업은 마지막 1주일이다.

**Slidev → Astro 전환.** 처음에는 [Slidev](https://sli.dev/)로 Ch.1~10 슬라이드를 만들었다(2/25~3/10). 하지만 Slidev는 프레젠테이션 도구일 뿐 시뮬레이션 임베드나 판서 기능을 붙이기엔 한계가 있었다.

**시뮬레이션 집중 제작(3/13).** 하루 만에 41개를 만들었다. 6개로 시작해서, 물리 오류를 수정하고(자유낙하 근 선택, 에너지 보존 비물리적 속도 반전 등), 15개를 추가하고, 전자기학·광학 범위 20개를 더 만들었다. 이 시점에서 시뮬레이션은 강의 슬라이드와 분리된 독립 HTML 파일이었다.

**Astro 통합(3/18~19).** Slidev를 버리고 Astro로 처음부터 다시 만들었다. 이틀 동안 SlideEngine(드로잉 캔버스, 키보드/스와이프 내비게이션, IndexedDB 저장), 강의 슬라이드 12개, 시뮬레이션 22개, SVG 다이어그램 ~60개를 전부 구현했다.

**테스트(3/20~21).** Playwright e2e 테스트 281개 작성. 시뮬레이션 수식 표시를 KaTeX 오버레이로 전환하고 라벨 겹침 문제를 수정했다.

### AI 활용

Claude를 전 과정에서 활용했다 — 교재 분석, 슬라이드 초안, 시뮬레이션 코드, SVG 다이어그램. 다만 AI가 생성한 콘텐츠를 그대로 쓰지는 않았다. 논리적 흐름, 학생 수준에 맞는 예시, 물리적 정확성은 직접 검토하고 수정했다. 특히 시뮬레이션의 물리 오류(마찰력 방향, 에너지 보존 계산, 충돌 타이밍 등)는 여러 차례 수정이 필요했다.

### 기술 스택

Astro (정적 사이트 생성), KaTeX (서버사이드 수식 렌더링), HTML5 Canvas (시뮬레이션 + 드로잉), IndexedDB (판서 저장), Playwright (e2e 테스트 281개), GitHub Pages (배포).
